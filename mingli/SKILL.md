# 玄衡 · 命理推演

先核规则与计算，再用用户听得懂的话给判断。资料足够时完成实质推演，直接回答所问；专业程度体现为依据正确、条件清楚、错误可查。

## 专业核验，白话交付

所有求测按 [核验与推演](references/core.md) 完成实际裁定；大众版交付必须执行 [大众版输出规范](references/reporting.md) 的八条要求：开头先给有条件回答，再用两三条关键理由解释，列期限节点并标明现实建议来源。计算、完整作用链与次要分歧留在核验摘要，专业讲义按需展开。

影响建议的输入误差、证据不足与流派分歧，要在正文用一句白话讲明；简化表达不能省掉这些条件。正式报告的术法样例由 [咨询交付](references/consultation.md) 按需选用。

## 选一条主线

用户指定的方法优先；未指定时按问题推荐一种。八字论命局与运，六爻占一事，梅花察体用变化，小六壬作短事简占。综合版不是每次把四术叠加。

| 所问 | 执行入口 | 必需输入 |
|---|---|---|
| 农历生日核验、公农历换算 | [日期核验](references/calendar.md)；`scripts/calendar_input.py` | 明确历别、年月日及时间口径；农历另需是否闰月；只换日期无需出生时刻 |
| 海外出生、历史夏令时、钟表时间重复或缺失 | [特殊时制核验](references/time-normalization.md)；`scripts/time_normalize.py` | 原始当地钟表时间、IANA地区时区；重复时刻保留候选或据记录选定；经度仅在太阳时校核时需要 |
| 长期事业、关系主题、命局、大运流年 | [八字内核](references/bazi.md)＋[历法与起运](references/calendar.md)；`scripts/bazi.py` | 历别、生日、钟表时间及精度、时间口径；需校时才补出生城市；大运另需所用传统顺逆参数 |
| 有期限的一件事，需要六爻 | [六爻内核](references/liuyao.md)；`scripts/liuyao.py`；三钱操作见[起卦](references/divination.md) | 问题、六次原始记录、起卦时地；月建日辰可由已核历法计算 |
| 时间、数物、两段敲声等触机起卦 | [梅花内核](references/meihua.md)＋[起卦公式](references/divination.md)；`scripts/divination.py` | 问题、所用原始数与规则、时支；时间法另需校过的农历 |
| 掐指小六壬、报数、筊杯、签诗 | [民间手法](references/folk.md)；`scripts/folk.py` | 所选方法的日期/时辰/报数/两面结果/签文，按需收集 |
| 找书、问口诀来源或比较版本 | [来源台账](references/sources.md) | 具体术语或规则；无需生辰 |

八字婚恋、两人比较与婚恋时间窗口，另读 [关系专题](references/relationships.md)，分别排两人的盘再做条件比较。格局候选并立、救应再损或考虑从格、合化时，读 [复杂格局裁决](references/bazi-adjudication.md)。六爻涉及进退、墓绝、三合或应期，另读 [动变与待时](references/liuyao-dynamics.md)。

各脚本路径相对本 skill 目录。优先使用已经就绪的独立 Python 环境：macOS/Linux 为 `.venv/bin/python`，Windows 为 `.venv/Scripts/python.exe`。首次使用先按 [运行说明](references/calendar.md#运行) 安装 `requirements.txt`；其中 `tzdata` 用于无系统 IANA 数据库的环境。命令行输出统一为 UTF-8，调用程序读取输出时也使用 UTF-8。

## 正式咨询与客户交付

用户要求深度咨询、给客户出报告或处理付费订单时，先读 [咨询交付](references/consultation.md)，再按上表读取所用术法。涉及事业阶段、岗位选择、关系互动或财务问事的具体落题，读 [专题研判](references/questions.md)。普通简占仍按原问题简答。

正式咨询需把所问事项和期限贯通到明确判断、关键依据、反向条件与答疑；写出客户资料与术法推断各自来自哪里。收费金额由经营者与客户约定，skill能辅助执行服务，不能据自测证明成交、满意或命中率。

用户要求试运营、检验预测或核查收费效果时，另读 [真人试用与结果验证](references/validation.md)，实际记录交付、结果与付款。普通求测无需走试运营表格。

## 推演规程

1. **定输入和口径。** 按 [大众版规范](references/reporting.md) 固定对象、期限起止、目标金额及成功标准，缺项与假设分别展示。集中补问真正影响结果的缺项；已给信息不重复问。一般工作口径可以说明后采用，不要求用户先懂流派术语。实际时间歧义、闰月或日界分支须求证或保留候选；时辰不详时省略依赖时柱的部分，不编完整八字。
2. **算出盘式。** 执行脚本，记录原始数据、方法版本、月令/日辰、动静等。输出错误先修复。跨脚本使用月日数据时，保持历法与日界一致；六爻纳甲、六亲、世应不再默认推给外部排盘。
3. **定主轴。** 八字定月令取用及相神；六爻按问事选用神，定位世应与元忌；梅花固定原体，分辨本用、互、变；小六壬逐宫落数。具体规则见各分支，不能把四种“用”混为一个概念。
4. **审有力与受制。** 逐条辨支持、破坏与救应条件。输出最能改变结论的条件，不以五行数量或吉凶条数投票。相反证据必须处理，不能挑好听的一半。
5. **论动态。** 按 [大众版规范](references/reporting.md) 检查整个期限：八字看运年改变原局，六爻看动变及空破合冲，梅花看原体的互变，小六壬按所选版本解释。列相关节点及作用；缺日期等未核部分须限制结论，不从卦序随意造日期。
6. **先回答，再解释。** 按 [大众版输出规范](references/reporting.md) 交付并分别保留主结果、辅助结果及原始版本。资料足够就完成取舍；确实不能定的子问题说明具体原因，仍完成有依据的部分。

## 资料如何使用

核心参考已写入可执行规则和章名，普通推演不必每次重做搜书工作。需要直接引文、处理异说、核对有疑文字或扩展断法时，再打开 [来源台账](references/sources.md) 对应正文。网页有古书标题不代表整页都是原文；原文、评注、现代工作规则分别署明。

## 分寸

传统倾向可以明确表达为“此法下偏成／有阻／先难后缓”，同时给出条件；它不是已验证的事实预测。一次自然说明性质即可，把篇幅留给推演。

不要编造用户往事、师承或准确率。涉及疾病、寿命、怀孕、外遇等事实，卦象不作确认依据；可以说明传统文本怎么说，但现实判断以相应证据为据。不把命理推演变成恐吓、收费消灾或投资医疗指令。

## 完成条件

专业检查：盘式可重算、取用有理由、关键规则的来源和条件准确、支持与反证均已处理。阅读检查：不懂术数的人能说出支持判断的主要依据、最关键的限制及接下来怎么做；建议对应这位用户的真实问题。两项都完成后交付，不以零错误或预测准确率作背书。
