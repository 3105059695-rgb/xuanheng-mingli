# 民间手法：小六壬掌诀、报数、筊杯、寺庙求签

核查：2026-09-14。用具体版本完成起课，再解释所得象义。用户已有结果就接着解读；尚未起课则按对应方法取得原始输入。三钱与梅花见 [divination.md](divination.md)。下文是内部起课和解释次序，客户答复按[大众版规范](reporting.md)先回答再解释，并固定对象、期限起止与成功标准。落宫不作对方财务、信用的事实证据，现实建议另标事实来源。

## 一、小六壬月日时掌诀

### 工作底本与手指定位

采用《萬寶玉匣記》，嵩山居士校阅，上海鸿文书局，1936，国家图书馆来源扫描，馆藏号 MG/B992.2/2；〈李淳風六壬時課〉在 **PDF第66–67页，书内卷下二十五、二十六**。[扫描与书目信息](https://commons.wikimedia.org/wiki/File:NLC416-15jh007692-106641_萬寶玉匣記.pdf)。这是后世传本文本，篇题的李淳风署名不等于作者年代已证。

本版六位依次：**大安 → 留连 → 速喜 → 赤口 → 小吉 → 空亡 → 大安**。“留连”在扫描写“留連”。手掌朝向自己，用拇指依次点三个手指的上下六处；以名字顺序为准，避免左右手图像镜像使“顺时针”误导。

```text
              食指          中指          无名指
上部          留连  ───→    速喜  ───→    赤口
               ↑                           ↓
根部          大安  ←───    空亡  ←───    小吉
```

扫描有掌图，文字小而局部模糊；上/下六处的清晰定位另对照 [GoldenLoong 公开项目的掌诀说明](https://goldenloong.github.io/Liu_Ren_divination/)。这张文字图帮助复算，不强求某条指纹或骨节具有特殊效果。“掐指”就是这套循环计数，不是额外一门术法。

### 取得什么资料

问清一件事与拟观察的时间范围；记录**起课时刻**的农历月、农历日、时支，及农历来自用户还是哪份历表。这里用农历月，不能拿八字按节气划分的月柱替代。子=1、丑=2、寅=3、卯=4、辰=5、巳=6、午=7、未=8、申=9、酉=10、戌=11、亥=12。

公历输入先按 [日期核验](calendar.md) 完成历法转换并核实大小月、闰月；已明确UTC+8标准时口径可用 `scripts/calendar_input.py`，其他时制另核。本起课脚本只检验数值范围，不能证明某年某农历日期实际存在。默认工作口径是当地民用钟表、00:00换日；时支子时包含23:00–00:59。这是为复算选定的现代输入约定，原篇未规定现代时区。

**闰月**：原篇没有处理条款。用户无指定流派时，本 skill 选“闰某月仍取某月号”，例如闰六月仍用6；报告显式写“本次按闰月同月号约定”，执行时传 `--leap-month --leap-policy repeat-month`。这是本次工作约定，不冒称底本条文。用户要求顺数第十三个月、闰月前后半分算等别法时，取得该版本后另列，不暗中切换。脚本默认拒绝未显式指定口径的闰月，用于捕获漏填。

**23:00前后与农历月底**：已指定子初换日的，先按该口径重新确定实际农历月日，再传 `--day-boundary zi-start`；该选项只记录口径，不自行把日期加一。若用户时刻不确定且跨边界，分别复算候选输入，列出落宫是否改变；不用卦象反推哪一个时刻“是真的”。

### 三段计算：每段起点都计一

1. 拇指点大安，称“正月”；依顺序数到农历月数，记月位。
2. 保持在月位，称“初一”；依顺序数到农历日数，记日位。
3. 保持在日位，称“子时”；依顺序数到时支序数，最后的时位为本课计算终位；它不等同于咨询中另行冻结的主预测结果。

关键是每段原地计一：初一、子时不会额外移动。以大安的零基索引为0，终位为 `(月 + 日 + 时序 - 3) mod 6`；公式只作交叉核对，报告仍保留三段落位。

底本原例：三月初五辰时。

| 段 | 实际计数 | 落位 |
|---|---|---|
| 月 | 大安1 → 留连2 → 速喜3 | 速喜 |
| 日 | 速喜1 → 赤口2 → 小吉3 → 空亡4 → 大安5 | 大安 |
| 时 | 大安子1 → 留连丑2 → 速喜寅3 → 赤口卯4 → 小吉辰5 | 小吉 |

```bash
python3 scripts/folk.py xiaoliuren-time --month 3 --day 5 --hour 辰 --calendar-source '1936底本算例'
```

规则版本 `wanbao-yuxia-1936-inclusive-v1`。脚本输出起点、次数、每一步、三段落位、终位、来源和日期口径。三段落位保留在核验记录；普通答复按大众版顺序，教学或争议复核时才展开逐步记录。

### 从落宫走到判断

本表按扫描六段口诀整理。附配是该版本内的传统对应；数字没有给出可通用的时间单位，不自动扩张成“几天必发生”。

| 宫 | 扫描附配 | 口诀数字 | 可抓取的传统主象 | 对应问题的观察点 |
|---|---|---|---|---|
| 大安 | 木、青龙 | 一五七 | 安定、守常、未动 | 原安排能否持续，是否确有变动消息 |
| 留连 | 水、玄武 | 二八十 | 迟滞、牵连、未回 | 卡在哪项手续、回复或未了事项 |
| 速喜 | 火、朱雀 | 三六九 | 消息、较快的进展 | 消息是否有具体时间、人物与可核实内容 |
| 赤口 | 金、白虎 | 四七十 | 争执、言语冲突 | 条款、误解、沟通语气与争议证据 |
| 小吉 | 木、六合 | 一五七 | 和合、商量、有人相助 | 谁能协商、帮忙，条件能否谈拢 |
| 空亡 | 土、勾陈 | 三六九 | 信音少、落空、事情不长 | 承诺是否落实、资料是否缺失，是否需备用方案 |

顺序是“终位主象 → 与问题有关的传统对应 → 有条件的解释 → 可观察事实”。如原例问一次合作洽谈：小吉取协商、和合之象，可读作传统上偏利接洽；现实观察点是对方是否落实会面、交付范围与下一步。不能从小吉独自推出具体金额、合同必签或对方真实动机。

扫描的日/月中间位主要承担起算。把月、日、时三宫分别解释为过去、现在、未来，属于另一些现代方法；若使用，注明现代叙事层，不说这是本篇规定。该篇没有完整“三宫生克强弱评分”，不把五行附配临时拼成自创吉凶模型。

**已校出的异文**：扫描第66页大安是“求财在坤方”，网上维基转录为“求谋在神方”；扫描第67页空亡数字为“三六九”，维基转录为“一五七”。本表从扫描，不混用不同网文的小吉属土、空亡属水等附配。健康、寿夭等旧断语只作为文本史解释，不直接照断真人。

## 二、报数小六壬：现代工作变体

采用三个数接续数六宫的公开流传方式；清晰实例见 [GoldenLoong 项目“掐算数字的由来／示例”](https://goldenloong.github.io/Liu_Ren_divination/)。这里只据发布者的规则说明证明当代存在这套方法，不采用网页未经论证的古代作者故事。

让用户一次报三个**正整数**，按原顺序记录，不把不喜欢的结果重新选号。第一数从大安起，第二数从第一数落宫起，第三数从第二数落宫起；每段原地计一，余数零落第六位而非“第零宫”。本 skill 选定只接受正整数；0、负数、小数要重取输入，不能偷偷把0改6。上限为10¹²，长计数输出整圈数和前30步。

```bash
python3 scripts/folk.py xiaoliuren-numbers 3 3 3
```

结果为速喜 → 小吉 → 大安，与公开示例一致。规则版本 `mingli-three-positive-numbers-inclusive-v1`。第三宫是主落点；若按该当代方法把三宫读作“开始、过程、收束”，应明说是现代三段读法。上述三宫可形成“消息牵动—协商推进—回归稳定”的象义脉络，再用事实核对；它不构成三条独立的预测证据。

报数不需要再收生日。用户要电脑代取时如实标记模拟，保留生成出的三个数并传 `--provenance simulated`；计算器本身不假装已替用户掐算、投掷或通神。

## 三、筊杯：取得两枚朝上的物理面

采用 [台湾交通部观光署“求神问卜”](https://www.tad.gov.tw/m1.aspx?sNo=0027010) 的面与名称对应；实际到寺庙依该寺说明。让用户记录两枚筊**朝上的是平面还是凸面**，不要只给阴阳名称或“凸面着地”。

| 朝上的两面 | 本版名称 | 民俗含义 |
|---|---|---|
| 一平一凸 | 圣筊 | 允诺、肯定 |
| 两平 | 笑筊 | 未定 |
| 两凸 | 怒筊 | 否定；龙山寺求签说明称阴筊 |

操作：确定一句能回答允否的问题 → 用户实掷并记录两面 → 分类 → 按所在寺庙的对应阶段说明下一步。已有结果直接分类，不再掷到喜欢为止。一凸一平仍是圣筊，两枚次序不影响分类。

```bash
python3 scripts/folk.py jiaobei flat convex
```

脚本记录 `user-reported`，仅分类用户报告的物理结果，不验证神意，也不推断真实世界事件的概率。确为模拟的输入传 `--provenance simulated`。

## 四、寺庙求签与解签：艋舺龙山寺观音签工作示例

[寺方“如何求籤”](https://lungshan.org.tw/Tour_Guide/search) 可直接核查以下流程。先固定寺庙、签系、一件问题；已有签文的直接进入解读，不必补做现场仪式。

1. **允许求签**：该寺现场先按其参拜流程，再请求一圣筊。圣筊可抽签；笑筊重新说明后再问；阴筊表示本次不允求签。这一阶段不是连续三圣筊。
2. **取签号**：获允后抽一支，记号并按寺方要求放回。
3. **确认这支签**：就这个签号求连续三圣筊；任何笑筊或阴筊，按该寺流程重新抽签号。不能把中途失败后的下一圣筊接着累计。
4. **取得对应原文**：寺庙＋签系＋签号绑定。该寺同时有观音签和关帝签，“第十八签”不足以唯一定位。核对用户签纸或该寺原文，不跨庙拼签。

确认同一个签号的记录可运行：

```bash
python3 scripts/folk.py longshan-lot fc cf fc
```

`f`为平面朝上、`c`为凸面朝上；此例三次圣筊返回 `confirmed`。`fc ff` 返回 `redraw-lot`；`fc ff fc` 被拒绝，因为第二次已结束这支签的确认。这是流程核查，不是提高预测准确率。每条记录在报告中绑定寺庙、签系及签号；脚本不保存签号，也不会检查不同调用是否属于同一支签。不能把不同签号的记录拼成连续三次。

解签按五项完成：①原文及版本，②逐句白话，③典故可核实的部分，④与本问题相合和不相合的意象，⑤下一步可观察或执行的事。把“签里写什么”和“本次如何理解”分开；没有足够出处时标“用户提供签文，版本未核”。不补造典故、诗句、上中下签等级。

寺方现场可能有姓名、生日、住址的禀告习俗；在线文本解读不需要完整住址。上述流程是具名寺庙版本，不推广成各地统一仪轨。
