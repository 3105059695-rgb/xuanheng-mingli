# 正式咨询：从客户问题到完整交付

用户要深度咨询、接待客户、制作付费报告时读取。此页是本 skill 的服务工作规范，术法仍执行各分支规则。经营者提到某个价格，不会自动把未验证能力提升为可承诺结果。

首次制作正式报告时，八字参照 [客户样例](consultation-example.md)，六爻参照 [取用、作用与裁定示范](liuyao-example.md)；其他方法按 [报告规范](reporting.md) 调整详略。八字的完整计算与出处另见 [对应核验摘要](consultation-audit-example.md)。示例均为合成资料；每位客户重新排盘、取用和落题，不复制结论。

## 接待前确定本次能完成什么

先按 [大众版规范](reporting.md) 固定对象、主问题、期限起止与口径、目标金额/币种或不适用、成功标准和辅助结果；已知事实、缺项及假设分别记录，再记主术法和交付形式。需要补资料时集中问真正影响结果的项目。长篇命盘不等于回答了问题；一件事也不需要必做四术。

默认建议一次深度咨询聚焦一个主问题，可带两项直接相关追问。客户要求其他范围时协商调整，不把该数量伪称术法限制。已约定范围、时长、价格和交付期限优先；未约定时只能提出方案，不写成双方已经购买或接受。

客户问“整体看看”时，可先给原局结构与运程总览，再邀请其选最值得深入的一项。重点问题没有明确前，不擅自把婚恋、疾病、财富、家庭全覆盖叫作详批。已有明确选项时，按 [专题研判](questions.md) 对称比较，不把现有职业样例的“暂选A”当成默认结论。

按 [核验与推演](core.md) 分开用户事实、排盘计算、传统规则判断、现实情境解释四类来源。客户说自己近期离职，报告就写“你提供的离职背景”，不能在回顾中变成“命盘算出你今年离职”。为解释问题取得背景是正常接待；用背景冒充事先独立命中会破坏交付可信度。

## 先形成可交付的研判

依 [专题研判](questions.md) 把客户原话拆成能够逐题回答的事项。每个主答复先形成一个紧凑的证据单元，供核验使用；成文时按 [客户表达](reporting.md) 写成有依据、有判断、有行动的答复，下表留作工作记录：

| 项目 | 必须落到什么 |
|---|---|
| 对象、期限与标准 | 沿用原话和选项，固定起止、目标金额/不适用与主成功标准；缺失/假设明示 |
| 传统主判断 | 用明确但有条件的倾向回应，例如本期宜稳后动、某一条件成立后偏可推进 |
| 决定性依据 | 具体干支、爻位、体用等怎样改变所用结构；保留足以让人核对的推演摘要 |
| 最强反证 | 本盘哪一项不支持主判断；为什么尚未推翻它，或何时会推翻 |
| 现实对应 | 标明情境解释与用户事实的区别；现实建议另列其事实来源 |
| 时间与转折 | 核对整个期限的相关节点及作用；未核日期或交界如何限制主判断 |
| 下一步与留验 | 主结果、辅助结果各留原句/期限/标准及版本，辅助发生不替代主结果 |

计算和资料足够时，必须完成这些单元。把“要看旺衰、要查运年”留作整段结尾只交付了计划：继续用现有盘、真实运年落实判断。确因现有规则或精度不能裁定时，明确尚不能回答的具体子问题，完成不依赖它的部分，并与客户重新确定范围。

辅助术法只处理另一项清楚的问题，并记录独立输入。若八字与六爻对同一问题看法不同，列出各自回答的对象、期限和依据；同向也只表示两个传统解释同向，不能当作统计独立验证。没有投掷、声音或报数，就没有相应的实际起卦；客户明确要模拟时才模拟并标明。

## 面谈如何展开

经营者可把线上会谈分配为：确认问题、先给有条件回答、解释两三条关键理由、听取澄清、单列现实建议与解决追问。时长按套餐安排，不要求模型机械输出每一分钟的逐字稿，也不把阅读一份文本的估计时长当作已完成面谈。

开头简短界定客户的问题和期限；服务性质与AI辅助情况用一句说明。按 [大众版规范](reporting.md) 先给本题的有条件回答，再解释两三条关键理由、核对期限节点，单列有事实来源的现实建议。完整盘表和核验流程留在摘要，面谈以客户的问题推进。

客户说“不符合”时，先记录哪一句、发生了什么事实；检查输入、口径及原判断是否过度。需要修订就保留原断和修订原因；仍不支持则承认该判断未得到支持，不归因于客户心诚与否。

客户撤回或更正出生时刻时，按 [历法](calendar.md) 重新审查受影响的柱、结构和起运。只删时柱仍可能留下错误的交运年份。客户仅补充岗位或关系事实时，则先检视它是否满足原先的改判条件，保持命盘输入不变，记录是现实信息更新。

追问按它改变了什么来答，补足本次交付：

| 客户追问 | 要完成的答复 |
|---|---|
| “到底选哪个／能不能？” | 重申已支持的主判断和最重要条件；确实不足以选时点明决定性缺项，不用更强语气替代证据 |
| “为什么今年和明年不同？” | 回到已算运年，按 [专题研判](questions.md) 解释一处实质变化及其对建议的影响；无足够差异就合并阶段 |
| “这些我都知道，付费买到了什么？” | 对照原问题指出这次实际完成的比较或传统推演、仍缺的答案；用现有资料补足能完成的部分。确无新增价值时承认，不用书目数量、工作时长或神秘身份证明价格合理，也不擅自承诺退费条款 |
| “和你说的不一样。” | 定位被反驳的原句和新事实；区分原先过度判断、输入错误与现实变化。不能把客户反驳改写成性格特征来维持原断 |
| “到期了，只发生一部分。” | 对照原事件和期限：电话意向不是书面录用，承诺付款不是到账。主结果按原标准判定，预设辅助事件另记各自结果；不以辅助替代主结果，下一次建议另写，不回改原断 |

普通追问无需每次展示工作表。需要实际留验、汇总效果或试运营时，才读 [结果验证](validation.md)。

## 交付给客户什么

正式报告的顺序、长度和术语控制统一执行 [客户表达](reporting.md)。开头先给有条件回答，随后用两三条关键理由解释，按规范列期限节点、缺项和现实建议来源。核验摘要保存完整输入、计算与规则定位，两者结论一致。

正式报告按实际约定交付。字数、页数、引用数量不等于深度；先检查有没有解决问题，再决定是否需要更多内容。只有技能文件不等于已经生成客户报告；只有报告也不等于完成了约定语音咨询。

普通短问答无需生成文件；用户要客户文件时再按其格式制作。客户资料仅用于当前交付，未经同意不公开为案例或评价。不自动替经营者收款、发给客户、预约或设后续提醒；对外动作按实际授权执行。

## 交付前审阅

经营者或报告生成者核对实际成品：每个承诺的问题都有回答；主要结论能回指具体规则；已给事实未冒充算出；盘表与运表一致；反向条件已处理；时间精度符合实现；没有空模板、伪造经历、师承、评论或成功率。任何未完成项缩小到明确范围处理，不能用“资料供参考”一笔带过。

检查报告的个案针对性和新增内容，按 [白话报告](reporting.md) 的最终检查执行；仅保留客户姓名、岗位名称或已知困扰不算完成个性化分析。

## 付费价值与复核

服务价值可来自认真准备、有来源的推演、清楚解释、完整答疑与可复核的书面记录。愿付多少钱和是否认为值得须靠真实客户体验与实际付款观察；其他商家标价、代码测试、模拟客户赞扬都不能代替这项证据。

需试运营或检验收费效果时，按 [真人试用与结果验证](validation.md) 明确约定、保存原判断并分别记录理解、实用价值、预测结果和实际付款；提议的优惠、退款或回访条款仍是草案，未经采用不擅自作承诺。

到期复核是单独一次实际工作。可现在准备复核表；只有收到授权并配置了可用提醒工具，才说已经安排回访。客户愿不愿续购由其自行决定，不以凶象、加钱才能知全貌或制造依赖促单。
