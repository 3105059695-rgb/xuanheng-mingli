# 海外、夏令时与太阳钟面核验

原始记录涉及海外当地时间、历史夏令时、拨钟重叠/缺失，或要求经度与真太阳时校核时读取。本工具把**原钟表记录 → 可能的绝对时刻 → 选定排盘口径**分开保存。固定 UTC+8 的四柱及交节仍由 [calendar.md](calendar.md) 的原引擎计算。

## 先确认的是记录口径

记录出生地点、原始公历日期与钟表时刻，说明是否已由别人扣除夏令时或改成北京时间。原件未注明时不要把推定说成原件内容。地区键由出生地点及当年实际用时确定，不从姓名、国籍或当前住址推定；`CST` 等缩写不足以确定时区。

采用固定 UTC+8、当地标准时、地方平太阳时或视太阳时，是命理流派的选择。把洛杉矶的同一瞬间换成 UTC+8，不等于证明海外命理必须用北京时间。本版只有**明确选定固定 UTC+8 口径**时能直接衔接现有完整四柱和起运计算。

## 可执行入口

先按 [运行说明](calendar.md#运行) 安装依赖，包含无系统 IANA 数据库时所需的 `tzdata`。在 skill 目录内，用已准备的 Python 环境运行（以下为 macOS/Linux shell 示例）：

```sh
.venv/bin/python scripts/time_normalize.py \
  --local '1991-07-01T12:00' --zone Asia/Shanghai \
  --day-boundary 00 --adopt-utc8 --uncertainty-minutes 10
```

Windows PowerShell 对应命令：

```powershell
.venv/Scripts/python.exe scripts/time_normalize.py --local '1991-07-01T12:00' --zone Asia/Shanghai --day-boundary 00 --adopt-utc8 --uncertainty-minutes 10
```

该样例按所用 IANA 规则识别夏令时 `+09:00`，输出同一时刻 `1991-07-01T11:00:00+08:00`，原输入仍保留 `12:00`。不得再人工减一小时。使用顶层 `bazi_input` 的四项参数调用 `bazi.py`，保留归一化 JSON 与排盘 JSON；gender、yun_sect 另按原排运约定提供。省略 `--adopt-utc8` 时只换算钟表，`bazi_ready=false`，不暗选时制。

归一化输出补出的秒 `00` 不提高原始记录精度：下游 `bazi.py` 只看到规范化字符串，可能不再提示“原输入没有秒”。核验摘要须从归一化的原文与警示继承这项限制；不能只保存下游盘表。历别也须先确认，未明确公历时，任何试算注明“公历分支假设”。

`--recorded-offset` 只填写原始材料已注明的数值偏移，负值例如 `--recorded-offset=-07:00`。它可消解重叠，也可发现地区/日期/记录不一致。

## 重叠与缺失如何处理

| 原始钟表记录 | 工具结果 | 后续动作 |
|---|---|---|
| 洛杉矶 2020-11-01 01:00 | `fold=0` 为 UTC 08:00，`fold=1` 为 UTC 09:00 | 未消歧时保留两候选；顶层不提供单一排盘参数。|
| 上海 1991-09-15 01:30 | 夏令时和标准时各一个候选 | 查原记录偏移或拨钟前后信息；分别排盘时分别保存，不能按经历择盘。|
| 上海 1991-04-14 02:30 | 当地钟面处于拨快缺口，报错 | 核实记录；不自动平移为 03:30。|
| 阿皮亚 2011-12-30 12:00 | 当地跳过整日，报错 | 先核历日和原件，不能补出一个出生瞬间。|

`fold=0/1` 是同一钟面先后两次，不是“夏/冬令时”的通用代号；有些地区只拨半小时，变化也可能与夏令时无关。以结果内的 UTC 瞬间与实际偏移为准。若用户已确认重叠中的哪一次，再传 `--fold 0` 或 `--fold 1`；普通时刻不要硬填 fold。

出生误差字段表示围绕**每个候选绝对时刻**的正负流逝分钟，输出对应 UTC+8 区间。它不能消除原钟表重叠，也不代表已经理解含糊的“凌晨一两点”。原记录含糊跨区间时先保留范围与候选，再分别查交节/换日/时辰边界。

## 经度与太阳时：能核对什么

提供有出处的出生地经度（东正西负），即可增加钟面对照：

```sh
.venv/bin/python scripts/time_normalize.py \
  --local '1991-07-01T12:00' --zone Asia/Shanghai \
  --day-boundary 00 --adopt-utc8 --longitude 116.4
```

此例的固定 UTC+8 钟面为 11:00（午时），地方平太阳钟面为 10:45:36（巳时），NOAA 均时差近似的视太阳钟面约 10:42（巳时）。116.4° 是教学输入，不能替真实客户自动填入；这项对照具体指出**时制选择可能改变时支**。

计算采用 `平太阳钟面 = UTC 钟面 + 4 × 东经度（分钟）`；近似视太阳钟面再加 NOAA 的均时差。均时差按同一瞬间的 UTC 日期、时刻计算分数年，闰年分母用 366。输出无时区标签的太阳钟面、时支与所选换日口径下的日标签，**不生成太阳时四柱**。

太阳钟面没有被当成新的绝对时刻：不得给 10:45:36 加上 `+08:00` 再送入原排盘，这会把出生瞬间挪动并误比较节气。固定 UTC+8 的年/月/起运继续按同一瞬间与库节气比较。要采用完整太阳时排盘，需要能分别处理绝对交节和当地日/时规则的引擎及独立核验；本版未实现这个入口。

该 NOAA 式是近似计算，本版未校准固定秒级或分钟级误差，未处理 UT1−UTC。靠近时辰或换日时只能提示复核，不能拿显示出的秒数决胜；经度取值误差也须保留。这里的传统时支对应属于本 Skill 的钟面比较约定，天文学来源不为命理断验背书。

## 数据证据与核验范围

- [Python zoneinfo 官方文档](https://docs.python.org/3/library/zoneinfo.html)：IANA 加载顺序、`fold`、`from_file` 及洛杉矶示例。脚本读取实际 TZif 字节后创建时区对象，同时记下文件 SHA256，避免缓存数据与所记证据错配。
- [PEP 495](https://peps.python.org/pep-0495/)：重叠、缺失与 UTC 往返。构造 datetime 本身不拒绝不存在的钟面，所以脚本先验双 fold，逐个做 UTC 往返；无候选时报错。
- [IANA asia 原始数据](https://data.iana.org/time-zones/tzdb/asia)：PRC 1986—1991 夏令时规则及其来源注释；[australasia 原始数据](https://data.iana.org/time-zones/tzdb/australasia)：Lord Howe 半小时变化与 Apia 跨日变更。
- [NOAA General Solar Position Calculations，第 1 页](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)：经度与近似均时差公式、东经为正、闰年分母。只采用这部分做敏感性核对，未宣称高精度天文排盘。
- [IANA 范围与准确性说明](https://data.iana.org/time-zones/tzdb/theory.html#scope)：历史地方记录尤其 1970 年前不完整，地区键无法证明某户或医院当年的实际钟表制度。未来规则会变，必须保存本次版本。JSON 记录实际系统 tzdb 版本/文件哈希，或官方 `tzdata` 包的版本；没有时区资料时停止，不从当前时差倒推。

本版回归覆盖已列历史样例、半小时与跨日变化、日期换算、冲突输入、原始记录保留、太阳钟面边界差异及与原排盘的交节衔接。它验证实现和所用资料被一致执行，不替代出生证核实、全球历史时制考证或预测效果验证。
